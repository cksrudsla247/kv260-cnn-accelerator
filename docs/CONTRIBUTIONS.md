# 본인 기여와 AI 활용

이 문서는 프로젝트에서 직접 수행한 구현·판단·실행과 AI 및 지도 과정의 도움을 구분합니다.

## 출발점: MLP 연산 블록

Weight-stationary와 최초 32×32 PE 배열은 과제로 주어진 조건입니다. 별도의 RTL skeleton 없이 PE·부호 곱셈기·adder tree·누산기·저장부를 구현했으며, 인터넷 자료를 참고하고 교수에게 설계 아이디어와 버퍼 구성에 관한 조언을 받았습니다. MLP 제어부는 AI와 함께 작성했고, 개념 확인·문법 수정·오류 분석에도 AI를 활용했습니다.

초기 MLP는 시뮬레이션과 합성을 수행했습니다. DMA·CSR·BRAM 기반 DRAM 모델을 추가한 후속 MLP 버전은 시뮬레이션까지 진행했습니다. 이 메모리 모델은 실제 외부 DDR 보드 검증을 의미하지 않습니다.

## CNN 확장에서 수행한 작업

- **기존 구현 재사용:** MLP의 PE와 곱셈기 등 연산 블록을 기반으로 확장했습니다. 공개 MLP와 CNN 소스를 비교하면 `PE.v`, `pe_col.v`, `bank_unpack.v`, `bn_regfile.v`는 동일하고, `multiplier.v`는 주석·공백을 제외하면 동일합니다. 누산기·adder tree·버퍼까지 전부 같은 코드는 아닙니다.
- **배열 선택:** LUT 자원 제약과 후보 비교를 확인하고 8×32 배열을 선택했습니다. 비교 코드의 작성에는 AI를 활용했습니다. 8개 행은 입력 성분의 reduction 폭, 32개 열은 병렬 출력 채널 수에 대응합니다.
- **공동 수정:** adder tree 변경·PE 파이프라인 추가·누산기의 BRAM 전환은 원인과 수정 방향을 판단하고 AI와 함께 수정했습니다.
- **Maxpool:** AI 초안을 직접 수정했습니다.
- **Controller·CSR:** Controller는 AI 초안을 실행했고 CSR는 코드를 확인했습니다. 이 부분을 직접 단독 설계·작성한 것으로 표현하지 않습니다.
- **실행:** 시뮬레이션 및 KV260 보드 실행 결과를 직접 확인했습니다. 코드 초안 작성과 도구 실행·결과 확인의 역할을 구분합니다.

CNN RTL 작성에는 생성형 AI를 폭넓게 활용했습니다. 이 역할 설명은 모든 모듈을 독립적으로 작성했다는 의미가 아닙니다. AXI·DMA·골든 모델·테스트벤치·보드용 C 코드의 개별 작성 주체를 이 문서에서 일괄적으로 본인 수행으로 분류하지 않습니다.

## 결과를 읽는 범위

- `928/928`: 입력 한 장의 6-layer 실행 후 남은 Conv2_2 784 word, Conv3 128 word, Affine 16 word의 비교입니다. 모든 레이어의 모든 중간 출력을 한 번에 비교한 수치가 아닙니다.
- 모델 정확도와 보드 출력 일치는 서로 다른 실험입니다. Python 정수 모델의 99.17%를 보드에서 MNIST 10,000장을 평가한 결과로 해석하지 않습니다.
- `68.8ms`: CSR 설정·레이어별 출력 등을 포함하는 보드의 전체 실행 루프 시간입니다. DDR 이미지 적재·readback과 최종 golden 비교는 제외됩니다.
- AXI burst 개선은 진행 중이며 개선 후 실측 성능을 완료 결과로 제시하지 않습니다.
